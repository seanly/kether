# Kether 实施计划

总体设计见 [../design.md](../design.md)。本目录每个文件是一个可独立交付的 issue，编号即建议实施顺序。每篇 issue 写目标、范围、实现要点和验收标准。

## 里程碑

| 里程碑 | 目标 | issues |
|---|---|---|
| **M0** 骨架 | 仓库能编译、测试、格式化 | 0001 |
| **M1** 身份与记录 | ID 与签名记录可单测，不入网 | 0002, 0003 |
| **M2** 入网与发现 | 启动即发布，能按 ID 解析、按类型搜索 | 0004, 0005 |
| **M3** 调用 | 握手、授权、Lightning 打桩支付、处理函数（**最小可用**） | 0006, 0007, 0008, 0009, 0010 |
| **M4** 链上支付 | Bitcoin 通道 | 0011 |
| **M5** 公网可达性 | AutoNAT、中继与打洞；人只传递一个 UUID；公网中继是 `cmd/kether` | 0012, 0013, 0014 |

## 约定

- 每个 issue 必须自带测试。Lightning、比特币节点、libp2p 网络在单测里用接口打桩或本地 Host，CI 不访问公网，也不要求真实钱包。
- 协议字段、错误码、签名域以 [design.md](../design.md) 为准。issue 里不重新定义编码。
- 日志、错误字符串、测试输出里不得出现私钥、种子、BOLT11 的 preimage。
- 落到磁盘的私钥文件权限为 `0600`。
- 空包用 `doc.go` 占位，等对应 issue 再填实现。
- 公共 API 从 `kether.Start` 进入。`cmd/twonode` 只在 0010 出现，不反向依赖演示程序。
