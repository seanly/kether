# 0013 用一个 UUID 入网

**里程碑** M5 · **依赖** 0012

## 目标

人只保存和传递一个随机 UUID。公网种子只配置 `host:port`。签名记录不再保存地址。拨号用 DHT 里已经连上的对端，中继和打洞留在库内部。

0012 的可达性选项保留。本 issue 把记录改成版本 2，并改掉 `kagent` 的常用命令。

## 范围

- 记录版本 2：增加 `uuid`，去掉 `addrs`。签名域 `kether/record/v2`
- DHT 键、`Hello`、`Node.ID()`、`ask --id` 使用这个 UUID
- 密钥文件为 32 字节私钥加 16 字节 UUID。32 字节旧文件在加载时补 UUID 并写回
- 种子接受 `host:port`。先做 TCP 上的 Noise 握手，学到 Peer ID 再 `Connect`
- `Connect` 用记录里的 `peer_id` 做 `FindPeer`，再拨 libp2p 地址簿里的地址，先直连再经中继
- `kagent` 常用命令收成 `serve --public`、`serve --seed host:port`、`ask --id <uuid>`。标准输出只有 `uuid <uuid>`

`peer_id` 仍留在签名正文里。类型、授权、支付、序号、过期时间不动。

## 实现要点

UUID 在 `id.Generate` 时生成一次，文本是小写 `8-4-4-4-12`。`record.Sign` 把它和公钥、`peer_id` 一起签进去。

`Start` 在创建 Host 之前把 `host:port` 解析成带 Peer ID 的 multiaddr，静态中继因此拿得到 Peer ID。已经带 `/p2p/<PeerID>` 的 multiaddr 原样保留，本地测试继续用 `Node.Addrs()`。

握手时服务方用连接上的公钥验 `Hello`，再按 UUID 读记录，核对 `peer_id`。调用方核对 Hello 里的 UUID、连接的 Peer ID 和记录里的公钥。

地址过滤不再写入记录。TTL 刷新仍递增 `seq`。

## 验收标准

- [x] 记录版本为 2，正文含 UUID，marshal 结果不含 multiaddr
- [x] 32 字节密钥文件加载后变成 48 字节，再次加载得到同一个 UUID，权限仍是 `0600`
- [x] `kagent` 用 `host:port` 入网，`ask --id` 打到指定 UUID，输出只有 `uuid` 行
- [x] 三个本地 Host 走中继握手：记录不含 multiaddr，`FindPeer` 之后连接的远端地址含 `p2p-circuit`
- [x] 本地测试不访问公网

## 完成情况

`TestRoundTrip` 确认记录不含 `/ip4/` 和 `p2p-circuit`。`TestUUIDFile` 覆盖旧密钥文件补 UUID。`TestRelayHandshake` 在记录无地址的前提下经中继握手。`cmd/kagent` 的 `TestEchoTwoNodes`、`TestSearch` 和 `TestServeSeedAndAskID` 用 `host:port` 拨种子。
